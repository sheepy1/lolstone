MeLoL 是一款在浏览器里玩的卡牌对战游戏。玩法照搬《炉石传说》的基础模式，卡牌角色换成《英雄联盟》的英雄。
第一阶段只做单机：玩家对 AI。自己玩，不考虑版权，不做账号、联机和付费。

初始卡池在 [cards-v1.md](cards-v1.md)。本文只讲规则、系统、表现和架构。

## 1. 目标与范围

要做到的：

- 浏览器打开就能和 AI 完整打一局。规则和炉石基础模式一致：英雄 30 点生命、法力上限 10、场上最多 7 个随从、手牌上限 10 张、牌库抽空就疲劳。
- 视听的完成度对标炉石：炉石在某个时刻有什么分量的反馈（出牌落地、攻击撞击、群体法术、受伤、死亡、胜负），我们在同一时刻就要有同等分量的反馈，动画时长和节奏也以它为参考。长相和视觉语言用"峡谷战局"，不照搬炉石的卡面、随从造型、英雄框和关键词表现。卡牌有悬停、拖拽、目标箭头的手感，有背景音乐、环境音和英雄语音。不看规则，光看画面和听声音，就知道场上发生了什么。
- 卡牌用数据描述。加一张常规卡只改数据文件，不改引擎。
- AI 会算斩杀、会做划算的交换、不会明显送。

第一版明确不做的：

- 联机、账号、服务器、排行榜。
- 武器、英雄牌、奥秘、任务、发现这类炉石后期机制。
- 收集、开包、经济系统。卡池全部解锁。
- 卡背、皮肤、表情、棋盘上可点的小玩意儿。这些是视听的加分项，等主干做完再加。

## 2. 对局规则

### 2.1 基本数值

| 项目 | 数值 |
| --- | --- |
| 英雄初始生命 | 30 |
| 牌库 | 30 张，同名最多 2 张，只能用本职业卡和中立卡 |
| 起手 | 先手 3 张，后手 4 张加一张「法力药水」 |
| 法力水晶上限 | 10 |
| 场上随从上限 | 7 |
| 手牌上限 | 10 |
| 英雄技能 | 2 费，每回合一次 |

### 2.2 开局

1. 随机决定先后手。
2. 双方洗牌，按 2.1 抓起手牌。
3. 换牌：每人可以把起手牌里任意几张换掉。引擎先从牌库顶补抽同样张数，新牌放在被换掉的位置，再把换掉的牌洗回牌库，所以不会立刻抽回刚换掉的牌。
4. 后手额外得到一张「法力药水」：0 费法术，使用后本回合多一个法力水晶。法力药水在发起手牌时就在手里，换牌时不能换它。

换牌是引擎里的一个阶段，不是界面层的事。对局从换牌阶段开始，双方各提交一次换牌动作（可以一张都不换，顺序不限），都提交后才进入对局阶段。动作和局面字段见 6.5，AI 的换牌策略见 4.2。

### 2.3 回合流程

1. 回合开始：当前玩家法力水晶上限 +1（最多 10），法力全部回满。
2. 触发"在你的回合开始时"的效果。
3. 抽一张牌。牌库为空则受到疲劳伤害（见 2.9）。
4. 行动阶段：出牌、攻击、用英雄技能，次数不限，顺序随意，直到玩家点"结束回合"。
5. 回合结束：触发"在你的回合结束时"的效果，"本回合"的临时增益消失，按 2.7 解冻。
6. 轮到对方。

### 2.4 出牌

随从牌：

- 支付费用，选一个位置放到场上。场上已有 7 个随从时不能出。
- 有战吼的随从先选目标再入场。需要目标的战吼没有合法目标时，随从照常入场，战吼不触发。
- 入场当回合不能攻击（召唤失调），有冲锋或突袭的例外。

法术牌：

- 支付费用，选目标，执行效果，牌进墓地。
- 需要目标的法术没有合法目标时不能使用。

英雄技能：每回合一次，2 费，目标规则和法术一样。

### 2.5 攻击

能攻击的条件，全部满足才行：

- 攻击力大于 0。
- 不是本回合入场的，有冲锋或突袭的除外。
- 本回合还没攻击过。有风怒的可以攻击两次。
- 没有被冻结。

目标规则：

- 可以打对方英雄或对方随从。
- 对方场上有嘲讽随从时，只能打嘲讽随从。处于潜行状态的嘲讽随从不算。
- 潜行随从不能被选为攻击目标。
- 突袭随从在入场当回合只能打随从，不能打英雄。

结算：攻击方和被攻击方同时对对方造成等于自身攻击力的伤害。英雄攻击力为 0，不反击。攻击之后攻击方失去潜行。

### 2.6 伤害、治疗与死亡

- 圣盾：受到伤害时，如果伤害大于 0，抵消这次伤害并失去圣盾。
- 剧毒：带剧毒的角色对随从造成伤害后，该随从直接死亡。攻击造成的伤害和本随从效果里 damage 动作造成的伤害都算，被圣盾挡下的伤害不算。
- 减益：生命值被减益降到 0 或以下的随从在死亡结算中死亡。减益不是受到伤害。
- 不是伤害致死的死亡：剧毒、消灭效果、减益导致的死亡都不算伤害致死，替代致命伤害的效果（泰达米尔）拦不住。特朗德尔的 -2/-2 把受伤的泰达米尔减到 0 血，泰达米尔死亡。
- 吸血：带吸血的角色造成多少伤害，就为自己一方的英雄恢复多少生命。攻击造成的伤害和本随从效果里 damage 动作造成的伤害都算。
- 法术伤害 +X：己方法术造成的伤害加 X。只影响法术牌，不影响英雄技能和战吼。
- 治疗不能超过生命上限。
- 死亡结算：以一个效果为单位，效果里的所有动作都执行完之后才检查；一次攻击结算完之后也检查。生命值小于等于 0 的随从同时离场，按入场顺序触发亡语。亡语可能再引发死亡，重复直到没有新的死亡，然后判定胜负。例子：暴风雪的伤害和冻结是同一个效果的两个动作，虚空幼虫被打死后亡语召唤出来的蠕虫不会被这张暴风雪冻结。

### 2.7 冻结

被冻结的角色不能攻击。解冻时机：在角色拥有者的回合结束时，如果这个冻结是在本回合之前施加的，就解冻。

换句话说：对方回合里被冻结的随从，到你的下个回合不能攻击，你那个回合结束时解冻。你自己回合里被冻结的随从，这回合结束时不解冻，下回合也不能攻击，下回合结束时才解冻。

实现上记录"冻结发生在第几回合"，回合结束时比较即可。沉默会同时解除冻结。

英雄不能被冻结。第一版英雄不攻击，冻结英雄的动作直接忽略，不发事件。魔法水晶箭选英雄时只有伤害生效。

### 2.8 法力

- 法力水晶上限每回合 +1，最多 10。
- 「法力药水」和「凛冬将至」这类效果：临时水晶只在本回合有效；空水晶是永久提高上限。上限已经是 10 时，空水晶效果改为抽一张牌。

### 2.9 疲劳、爆牌与满员

- 牌库为空时抽牌：不抽牌，英雄受到疲劳伤害。第一次 1 点，第二次 2 点，依次递增。
- 手牌已有 10 张时抽牌：抽到的牌直接销毁（爆牌），同时展示给双方。
- 手牌已有 10 张时有随从被移回手牌（李青、传送回城）：该随从直接销毁，不触发亡语。
- 场上已有 7 个随从时：从手牌出随从不合法；效果里的召唤不召唤，没有补偿；效果只有召唤的英雄技能和法术不能使用，第一版里是盖伦的「召集」。

### 2.10 胜负

每次死亡结算之后检查：一方英雄生命值小于等于 0，另一方获胜。双方同时小于等于 0 为平局。

### 2.11 随机与可复现

对局里所有随机事件（洗牌、随机目标、随机关键词）都从一个种子生成。同一个种子加同一串动作，必然得到同一个结果。这是回放、测试和 AI 模拟的基础。

### 2.12 召唤位置

- 从手牌打出的随从放在玩家选的位置。
- 战吼召唤的衍生物放在本随从右边，多个时依次向右。
- 亡语召唤的衍生物放在死者原来的位置，多个时从那个位置依次向右。
- 英雄技能和法术召唤的放在场上最右边。
- 位置不够时按上面的顺序能放几个放几个。

### 2.13 变形

- 变形出来的随从占原来的位置，是一个全新的随从：没有原来的增益、伤害和冻结，带自己卡面的关键词和效果，包括亡语。
- 变形不算死亡，不触发原随从的亡语。
- 变形出来的随从视为本回合刚入场，当回合不能攻击，有冲锋或突袭的例外。冰凤凰蛋在回合开始时变回的艾尼维亚这一回合不能攻击。
- 变形的目标可以是任何卡牌 id，不限于衍生物。

## 3. 卡牌

### 3.1 卡牌类型

| 类型 | 说明 |
| --- | --- |
| 随从 | 有费用、攻击力、生命值，可以带关键词和效果 |
| 法术 | 有费用和效果，用完进墓地 |
| 英雄技能 | 每个职业固定一个，不进牌库。数据里是 type 为 hero_power 的卡，效果用 cast 时机描述 |
| 衍生物 | 被效果召唤出来的随从或生成的牌，不能放进牌库 |

### 3.2 职业与英雄

职业按地区划分。每个职业有一个代表英雄，英雄技能对应他的招牌技能。随从牌全部是英雄，每个英雄只属于一个地区。中立卡用召唤师峡谷的小兵、野怪、元素亚龙，以及虚空生物和约德尔人。

第一版做四个职业：

| 地区 | 英雄 | 英雄技能（2 费） | 风格 |
| --- | --- | --- | --- |
| 德玛西亚 | 盖伦 | 召集：召唤一个 1/1 的德玛西亚士兵 | 铺场、增益、嘲讽、圣盾 |
| 诺克萨斯 | 德莱厄斯 | 诺克萨斯断头台：对敌方英雄造成 2 点伤害 | 快攻、直伤、吸血 |
| 艾欧尼亚 | 阿狸 | 灵魄：造成 1 点伤害 | 法术、潜行、连击、回手 |
| 弗雷尔卓德 | 艾希 | 寒冰箭：冻结一个敌方随从 | 冻结、大体型、嘲讽、法力加速 |

以后可以加的地区和定位：皮尔特沃夫与祖安（抽牌、法术伤害，金克丝或杰斯）、暗影岛（亡语、复活，锤石或莫德凯撒）、比尔吉沃特（随机、掠夺，普朗克或崔斯特）、恕瑞玛（成长，阿兹尔）、巨神峰（治疗、增益，索拉卡或潘森）。

### 3.3 关键词

| 关键词 | 定义 |
| --- | --- |
| 嘲讽 | 对方攻击时必须先打本随从。潜行时不生效 |
| 冲锋 | 入场当回合就能攻击，可以打英雄 |
| 突袭 | 入场当回合就能攻击，但只能打随从 |
| 圣盾 | 抵消受到的第一次伤害，然后失去圣盾 |
| 潜行 | 不能被攻击，也不能被对方的指向性效果选中。攻击之后失去潜行。群体效果照样打到 |
| 风怒 | 每回合可以攻击两次 |
| 吸血 | 造成的伤害同时为己方英雄恢复等量生命，攻击和自身效果造成的伤害都算 |
| 剧毒 | 对随从造成伤害后，该随从死亡，攻击和自身效果造成的伤害都算 |
| 法术伤害 +X | 己方法术的伤害加 X |
| 战吼 | 从手牌打出时触发 |
| 亡语 | 死亡时触发 |
| 连击 | 本回合已经使用过其他牌时，从手牌打出触发 |
| 激怒 | 生命值低于上限时获得效果，恢复满就失去 |
| 冻结 | 见 2.7 |
| 沉默 | 移除关键词、卡牌文本效果和所有增减益，攻击力和生命上限回到卡面。当前生命值超过新上限时降到上限，最低为 1。同时解除冻结 |

第一版实现全部关键词。连击和激怒只有少数卡用到，可以放在引擎的第二批。

数据里的表示：法术伤害和激怒带参数，不放在 keywords 数组里，用 static 效果描述（见 3.4）。圣盾就是一个关键词，失去圣盾就是从数组里移除它。

### 3.4 效果模型

一张卡的效果由三部分组成：什么时候触发（时机），做什么（动作），对谁做（目标）。绝大多数卡用这三部分的组合描述出来，不写代码。

触发时机：

| 时机 | 含义 |
| --- | --- |
| cast | 法术和英雄技能使用时 |
| battlecry | 战吼 |
| deathrattle | 亡语 |
| combo | 连击，条件满足时触发。一张卡可以同时有战吼和连击 |
| turn_start / turn_end | 拥有者的回合开始时 / 结束时。多个随从同时触发时按入场顺序 |
| on_kill | 本随从消灭一个随从之后 |
| static | 常驻被动，没有动作列表，有自己的参数：法术伤害 +X、激怒 |

"本随从消灭一个随从"的判定：本随从造成的伤害（攻击时不论是攻击方还是被攻击方，或者本随从效果里的 damage 动作）让对方随从在随后的死亡结算中死亡，包括剧毒导致的死亡。法术和英雄技能造成的死亡不算。易和科加斯都靠这条。

目标分两层。需要玩家选的目标在效果上声明一次，动作里用 chosen 引用它；自动目标直接写在动作里。

需要玩家选的目标（TargetSpec）：

| pick | 范围 |
| --- | --- |
| any_character | 任意英雄或随从 |
| any_minion | 任意随从 |
| enemy_minion | 敌方随从 |
| friendly_minion | 友方随从 |
| other_friendly_minion | 本随从以外的友方随从 |

可选条件 where：damaged，受伤的，生命值低于上限。潜行的敌方随从不在可选范围内。

自动目标（ActionTarget）：chosen、self、friendly_hero、enemy_hero、all_enemy_minions、all_minions、other_friendly_minions、random_enemy_minion、random_other_friendly_minion。

动作：

| 动作 | 参数 | 目标 |
| --- | --- | --- |
| damage | amount | 任意 |
| heal | amount | 任意 |
| buff | attack、health、keywords、duration（permanent 或 turn）。负数就是减益 | 任意 |
| summon | token（卡牌 id）、count | 没有目标，召唤到自己一方，位置见 2.12 |
| draw | count | 没有目标，拥有者抽 |
| freeze | 无 | 随从 |
| silence | 无 | 随从 |
| destroy | 无 | 随从 |
| bounce | 无 | 随从 |
| transform | into（任意卡牌 id） | 随从 |
| gain_mana | mode（empty 或 temp）、amount | 没有目标 |
| extra_attack | 无 | self |
| random_keyword | from（关键词列表） | self |

每个动作带一个表现用的 fx 字段：physical、fire、frost、holy、shadow 之一。招牌卡可以再带一个 fxId，表现层按 fxId 查专属特效注册表，没注册的按 fx 类型播。fxId 只用小写字母、数字、点、下划线，写成"英雄 key 小写.招式英文"，如 `anivia.glacial_storm`，清单在 m4-signature-fx.md。引擎不读这两个字段，原样放进事件。

规则：

- 一个效果可以有多个动作，按顺序执行，引用的都是同一个 chosen 目标。特朗德尔的战吼是两个 buff：chosen 的 -2/-2，然后 self 的 +2/+2。
- 需要选目标的法术和英雄技能，没有合法目标就不能用。需要选目标的战吼，没有合法目标时随从照常入场，战吼跳过。
- 连击的条件是"本回合已经使用过其他牌"，英雄技能不算，法力药水算。

类型定义：

```ts
type Keyword = 'taunt' | 'charge' | 'rush' | 'divine_shield' | 'stealth' | 'windfury' | 'lifesteal' | 'poisonous';
type Fx = 'physical' | 'fire' | 'frost' | 'holy' | 'shadow';
// 带 fx 的动作都可以再带 fxId?: string，招牌卡的专属特效 id，引擎原样透传

type TargetSpec = {
  pick: 'any_character' | 'any_minion' | 'enemy_minion' | 'friendly_minion' | 'other_friendly_minion';
  where?: { damaged?: boolean };
};

type ActionTarget =
  | 'chosen' | 'self' | 'friendly_hero' | 'enemy_hero'
  | 'all_enemy_minions' | 'all_minions' | 'other_friendly_minions'
  | 'random_enemy_minion' | 'random_other_friendly_minion';

type Action =
  | { kind: 'damage'; amount: number; target: ActionTarget; fx: Fx }
  | { kind: 'heal'; amount: number; target: ActionTarget; fx: Fx }
  | { kind: 'buff'; target: ActionTarget; attack?: number; health?: number; keywords?: Keyword[];
      duration: 'permanent' | 'turn'; fx: Fx }
  | { kind: 'summon'; token: string; count: number; fx: Fx }
  | { kind: 'draw'; count: number }
  | { kind: 'freeze'; target: ActionTarget; fx: Fx }
  | { kind: 'silence'; target: ActionTarget; fx: Fx }
  | { kind: 'destroy'; target: ActionTarget; fx: Fx }
  | { kind: 'bounce'; target: ActionTarget; fx: Fx }
  | { kind: 'transform'; target: ActionTarget; into: string; fx: Fx }
  | { kind: 'gain_mana'; mode: 'empty' | 'temp'; amount: number }
  | { kind: 'extra_attack'; target: 'self' }
  | { kind: 'random_keyword'; target: 'self'; from: Keyword[] };

type Effect =
  | { trigger: 'cast' | 'battlecry' | 'deathrattle' | 'combo' | 'turn_start' | 'turn_end' | 'on_kill';
      target?: TargetSpec;        // 只有 cast、battlecry、combo 可以声明
      actions: Action[] }
  | { trigger: 'static'; kind: 'spell_damage'; amount: number }
  | { trigger: 'static'; kind: 'enrage'; attack?: number; health?: number; keywords?: Keyword[] };
```

少数卡的效果用这套模型写不出来，走脚本：卡牌数据里只写脚本名，引擎里注册对应的函数。第一版需要脚本的卡在 cards-v1.md 的"实现分级"里列出，一共 2 张：菲奥娜、泰达米尔。新卡优先用数据描述，实在写不出来才加脚本。

引擎加载卡池时校验：

- 每张卡引用的动作、目标、衍生物、脚本都存在。
- 随从必有攻击和生命，法术和英雄技能没有。
- 动作里用了 chosen 的效果必须声明 target；声明了 target 的效果时机只能是 cast、battlecry、combo。
- static 效果只能出现在随从上。
- 英雄技能费用为 2，每个职业恰好一个。

卡面文本和效果是否一致由每张卡的单元测试保证。

### 3.6 身材基准

照炉石的经验公式：N 费随从，攻击加生命大约等于 2N + 1。带文本或关键词的卡从这个基准往下减，减多少看效果强度。

| 费用 | 白板身材 | 带效果的参考 |
| --- | --- | --- |
| 1 | 1/2 或 2/1 | |
| 2 | 2/3 或 3/2 | 2/2 带一个小效果 |
| 3 | 3/4 | 3/2 带冲锋，2/3 带亡语或抽牌 |
| 4 | 4/5 | 3/3 带战吼，3/4 带关键词 |
| 5 | 5/6 | 4/5 带战吼 |
| 6 | 6/7 | 5/5 带战吼 |
| 7 | 7/7 | 6/7 带战吼 |

法术参考：1 费 2 点伤害，2 费 3 点单体伤害，4 费 4 点任意伤害，4 费全场 2 点伤害，5 费消灭一个随从。

第一版不追求平衡，先把卡做出来，靠 AI 互打的胜率数据再调。有意偏离基准的卡记在 cards-v1 的"平衡调整记录"里。

### 3.7 身材按 LoL 定位

总身材仍按 3.6 的基准，这条管的是攻击和生命怎么分。每个英雄随从按它在 LoL 里的定位归类，攻血分配要符合该类的倾向。定位取 Data Dragon `champion.json` 的 `tags` 第一项，也就是客户端显示的主定位。tags 只有六个主定位，没有细分；战士的三档和坦克的两档按 LoL 维基的官方职业分类页（Fighter、Skirmisher、Tank 三页）查，每个英雄查到的归属记在 cards-v1 的核查表里。用户另有判断时以用户为准（易按维基是剑客，用户定为刺客，取攻击更高的刺客档）。

| 定位 | 攻血分配 | 典型身材 | 关键词和效果的倾向 |
| --- | --- | --- | --- |
| 坦克·先锋 | 生命明显高于攻击：生命 − 攻击 ≥ 3；3 费及以下 ≥ 2，且生命至少是攻击的两倍。先锋是开团的，攻击取这个范围里偏高的一端 | 3/6、3/7、4/7 | 突袭、冻结这类控制、战吼 |
| 坦克·守护者 | 数值规则同先锋，守护者是保人的，攻击取最低 | 1/4、2/5、2/7、3/7 | 嘲讽、圣盾、给友方护盾 |
| 战士·重装 | 攻击和生命接近，允许生命多 2：慢而耐打 | 3/3、3/5、6/7 | 激怒、随机关键词、群体战吼 |
| 战士·轻装 | 攻击和生命相差不超过 1，倾向偏攻 | 3/2、3/3、4/3、4/5 | 突袭、冲锋、连击 |
| 剑客 | 攻击等于生命加 1：攻击高，但比刺客多一点血。官方归在杀手类，和刺客并列，不在战士下 | 3/2、4/3、5/4、6/5 | 圣盾、击杀后再攻击、不受反击、致命伤害替代 |
| 刺客 | 攻击高于生命：攻击 ≥ 生命 + 1，生命压低换攻击和效果 | 3/2、4/2、5/3 | 潜行、连击、击杀后再攻击 |
| 射手 | 攻击高于生命：攻击 ≥ 生命 + 1，持续输出靠关键词体现 | 2/1、3/2、4/2、5/4 | 风怒、剧毒、突袭 |
| 法师 | 攻击不高于生命；总身材比基准低 1 到 2 点，差额给效果 | 1/2 带战吼、3/4 带法伤 | 法术伤害、战吼伤害、群体效果 |
| 辅助 | 攻击不超过 2（6 费以上不超过 3），生命中等，价值在作用于友方的效果 | 2/3、2/5、2/7 | 治疗、增益、圣盾、嘲讽 |

补充：

- 带剧毒的卡攻击力不计入判断，只看生命：刺客和射手的生命不超过费用。
- 平衡调整必须沿定位方向：加强刺客、剑客和射手加攻击或加效果，不加生命；加强坦克加生命或加嘲讽，不加攻击；加强法师加效果或法术伤害；加强辅助加效果；战士两边都可以加，轻装保持相差不超过 1，重装保持生命不多于攻击 2。削弱同理反向。为平衡偏离基准总身材可以，记在 cards-v1 的平衡调整记录里；偏离定位的攻血分配不行。
- 这条只管英雄随从。小兵、野怪、亚龙、虚空生物不受限制，衍生物按它的来源卡定。
- 核查结果和建议在 cards-v1 的"定位核查表"。

## 4. AI

### 4.1 难度分级

| 级别 | 做法 | 用途 |
| --- | --- | --- |
| L0 随机 | 从合法动作里随机选 | 引擎测试 |
| L1 贪心 | 每一步枚举所有合法动作，各模拟一步，选评估分最高的 | 第一版默认 |
| L2 回合内搜索 | 在一个回合内搜索动作序列，考虑对方下回合的威胁 | 第二版 |
| L3 蒙特卡洛树搜索 | 带隐藏信息抽样的 MCTS | 以后 |

### 4.2 L1 贪心

换牌：换掉费用大于等于 4 的牌。后手有法力药水，最多保留一张 4 费的。

出牌和攻击：

```
循环：
  如果能斩杀（可用攻击 + 直伤法术 + 英雄技能，扣掉嘲讽挡住的部分，够打死对方英雄；要能估算到"易打死嘲讽之后再攻击英雄"这类先清嘲讽再打脸的序列）：执行斩杀序列，结束
  列出所有合法动作，不含"结束回合"
  对每个动作：复制局面，执行，算评估分
  最高分比当前局面高出一个阈值：执行它，继续循环
  否则：结束回合
```

要点：

- 一次只看一步，所以 AI 不会为了下回合留牌。对第一版够用。
- 有些动作做完本身不加分，价值在于为下一步创造条件，这几类动作要再往后看一步，分数取"做完它再做最好的一步"和"只做它"两者中高的那个：当前法力变多（法力药水）；本回合打出的第一张牌，而手里还有连击牌；把自己的随从移回手牌（传送回城）；攻击后攻击者多了攻击次数（易）。
- 阈值初始取 0.5 分。比它小的提升不值得动，直接结束回合。
- 模拟用的局面要遮掉隐藏信息：对方手牌和双方牌库换成占位牌。AI 不能看对方手牌。
- 模拟用独立的随机数流，不消耗真实对局的随机数。
- 每个动作模拟一次，一回合最多几十次模拟，主线程同步跑就行。
- AI 的动作之间要留出"思考"间隔，不要一瞬间全打完。炉石里对手每个动作之间都有停顿，这是手感的一部分。间隔由驱动 AI 的对局层插进事件队列，不是引擎的事，见 6.4。规则（已实现，参数在 match.ts 的 AI_PACE）：同一回合第一个动作前随机停 0.8 到 1.5 秒，之后每个动作的停顿乘 0.6，最短 0.4 秒，随机浮动 ±15%；已经没有别的可做、决定结束回合前只停 0.2 秒。
- 对手回合的时长口径：前几分钟里动作不超过 5 个的回合必须在 10 秒以内；之后的回合按平均每个动作约 1.5 秒（思考加动画）控制，不设硬上限。M3 实测 7 个动作的回合 13.25 秒，其中思考只占 3.65 秒，其余是事件动画，所以时长主要靠表现层的组间重叠（分镜表 1.7）和展示时长控制，不靠继续压思考。

### 4.3 评估函数

```
分数 =
    wHp   × (我方英雄生命 − 敌方英雄生命)
  + Σ 我方随从价值 − Σ 敌方随从价值
  + wHand × (我方手牌数 − 敌方手牌数)
  + wMana × (min(我方法力上限, 10) − min(敌方法力上限, 10))
  + 对方死亡 +1000，我方死亡 −1000

随从价值 = 攻击 × 1.0 + 生命 × 0.8 + 0.5
  + 嘲讽 1 + 圣盾 攻击×0.5 + 风怒 攻击×0.8 + 潜行 0.5 + 吸血 0.5 + 剧毒 2 + 法术伤害 1
  被冻结的随从攻击按 0 算
```

权重按职业风格调：诺克萨斯的 wHp 高（1.5），弗雷尔卓德低（0.6），其他 1.0。wHand 取 0.7。这些是起点，拿 AI 互打的胜率调。

法力上限项的权重 wMana 取 2。没有这一项时，凛冬将至这类获得空水晶的牌打出去只会让手牌少一张，AI 永远不会打。取 2 时，一个水晶抵一张手牌（0.7 分）还多 1.3 分：比结束回合好，但比不过一个像样的 2 费随从（2/3 约 +4.2 分），所以 AI 只在 2 费没有更好用法时才打它，实测平均在自己的第 4 回合。法力上限到 10 以后这一项不再加分；上限已满时空水晶改为抽牌，手牌数不变，AI 也不会去打。

### 4.4 L2 回合内搜索

在一个回合内对动作序列做深度优先搜索，节点上限几千个，按局面哈希去重（出牌顺序不同但结果一样的只算一次）。每条序列结算到回合结束，分数 = 评估分 − 对方下回合能打到我方英雄的伤害 × 0.5。选最高分的序列执行。放到 Web Worker 里跑，避免卡 UI。

### 4.5 AI 需要的引擎接口

- `listLegalActions(state, player)`：所有合法动作，含出牌的每种目标和位置组合。
- `applyAction(state, action)`：纯函数，返回新局面和事件列表，不改入参。
- `maskHidden(state, player)`：遮掉对方手牌和牌库。
- `forkRng(state)`：给模拟用的独立随机数流。

## 5. 界面与视听

完成度对标炉石，长相不照搬炉石。炉石在某个时刻有什么分量的反馈，这里在同一时刻就要有同等分量的反馈，动画时长和节奏以它为参考。视觉语言取自 LoL 对局，玩家在峡谷里看惯的护盾、buff 图标、水晶枢纽，在这里表示同样的意思；不照搬炉石的卡面、随从造型、英雄框和关键词表现。验收按 5.6 的清单逐条过。

- 棋盘是召唤师峡谷的俯视图，中线是河道，上半边对手、下半边我方。棋盘不是一张贴图：细分平面按高度图位移出地形起伏，河道挖下去用水材质，枢纽平台和几处墙体是几何体，卡牌和随从的影子落在真实的起伏上。有缓慢的环境动画（水面、飘动的草），不抢注意力。

### 5.3 操作与反馈

每个操作都有即时反馈，操作对象的状态一眼能看出来：

- 手牌排成扇形，张数多时自动收紧。悬停某张时它放大上浮到清晰可读，邻牌让开。能出的牌有绿色发光边，费用不够的变暗。
- 拖起一张牌，像从台面上拿起一张实体卡：它离开台面一点高度，用阻尼弹簧跟随鼠标，有一点滞后，不是贴着鼠标走；按移动速度和方向倾斜，停下来时回正并有小幅回弹。手牌区重排补位。随从牌拖到我方随从行时，目标位置出现空位阴影，场上随从让开；松手就是入场位置。法术牌拖出手牌区就进入施法状态，无目标法术拖到棋盘任意处松手即用。
- 需要目标时，从来源拉出一条红色曲线箭头跟着鼠标，合法目标有红色准星高亮，非法目标变暗。右键或拖回原位取消。
- 能攻击的随从有绿色发光边，鼠标按住它拉出攻击箭头。被冻结的盖着冰层，召唤失调的没有光边。
- 悬停场上随从或对手打出的牌，左侧显示放大的完整卡面。大卡是场景里的卡牌网格，正对镜头、和场上同一套光照，不是叠在画布上的 DOM；只有关键词解释用 DOM 提示。
- 对方行动期间，鼠标变成"等待"状态，手牌不能拖，但可以悬停看牌。
- 一局中的任何动画，点击棋盘或按空格加速到三倍。

### 5.4 视觉风格

方向是"峡谷战局"：所有状态都用 LoL 对局里玩家看惯的方式表示，不发明新的视觉语言，也不照搬别的卡牌游戏的外观。

场上的随从：

- 方形英雄头像（Data Dragon 120×120 头像图）嵌在底座里，没有血条。攻击和生命是两个对称的徽章，嵌在底座内部的左下角（攻击）和右下角（生命），完全在边框以内，同样大小，凸起的立体感，造型用我们自己的海克斯风格；和手牌卡面上攻击左下、生命右下的位置一一对应，这是卡牌游戏的通用做法，不算照搬谁的外观。受伤时生命徽章的数字变红，增益后高于卡面的数字变绿，减益低于卡面的变红。两个数字都要一眼读得出；生命上限超过 10 也只是数字变大。
- 圣盾：生命徽章外圈亮一圈白色护盾环，随从外罩一层半透明的发光外壳；被打破时护盾环和外壳一起碎掉。
- 嘲讽：头像外一圈金色描边，加一个盾形小图标。
- 潜行：头像半透明，加一个"视野被遮"的小图标。
- 冻结：头像上覆一层冰。
- 剧毒、吸血、风怒、法术伤害：底座上沿（头像上方）一排 buff 风格的小图标，悬停显示说明。图标用 LoL 自己的技能、召唤师技能、物品和被动图标，比如嘲讽用拉莫斯的 E，冲锋用疾跑，剧毒用图奇的被动，来源见 5.9。英雄技能图标也用对应英雄的技能图标。
- 增益后的数值变绿，减益变红。能攻击的头像有绿色描边，召唤失调的略暗，和 5.3 一致。

镜头与光照：

- 真 3D 场景。固定透视镜头斜俯视棋盘，俯角大约 50° 到 60°。我方手牌靠近镜头，对方区域在远处，有纵深。
- 一盏方向光加环境光，实时阴影。卡牌、随从底座、水晶枢纽都有厚度，在台面上投下阴影。
- ACES 色调映射，泛光（bloom）后处理。发光的东西（能出的牌、能攻击的随从、技能图标、护盾环）靠自发光材质加 bloom 做，不靠描边贴图。
- 手牌不平贴着正对镜头：有倾角，能看到厚度边，表面有随视角流动的高光（清漆层或带金属度的材质）。悬停时卡牌抬起、倾角略减但不完全转正，保留立体感；拖拽按 5.3 的拿起手感。

上面几种随从状态在 3D 里的做法：

- 冻结：头像和底座外覆一层半透明冰材质，带高光。
- 圣盾：随从外一层半透明的发光外壳，生命徽章外圈同时亮起护盾环；打破时外壳碎成粒子。
- 嘲讽：底座边缘一圈金色自发光描边。
- 潜行：材质透明度降低，加一层淡烟粒子。
- 能攻击：底座绿色自发光描边。召唤失调：材质略暗。

水晶枢纽（英雄）：

- 英雄头像是圆形，嵌在一个暗色金属的六边形矮台座上；生命徽章在台座右前方，和随从的数值徽章同一套海克斯风格。
- 台座六个侧面各嵌一颗半球形小灯，在侧面正中朝外，共 6 颗：外层是透明玻璃罩，带高光和菲涅尔边缘亮光；里面是一个小的自发光灯芯，我方蓝色、对方红色；每颗灯外围一圈金属灯座。只有灯芯参与泛光。
- 呼吸：周期 2.6 秒，幅度约 12%，双方错开半拍。自己的回合亮度系数 1.0，对方回合 0.3，换回合时 0.5 秒平滑过渡。
- 低血提示：生命低于 10 时按生命比例留几颗亮着，9 点 6 颗、5 点 3 颗、1 到 2 点 2 颗，其余熄灭；从后排往前熄，最后剩左前那颗（右前那颗被生命徽章挡住一半，不留它）。亮着的几颗改为快速、不规则的闪烁，周期 0.7 秒。
- 不能被选为目标时，整组灯压暗。
- 输掉时，灯芯猛亮一下，再整颗缩没，和失败演出（分镜表 E29）衔接。
- 参数集中在 NEXUS_LAMP，/dev/fx 的"枢纽小灯"面板可以现场调。实现在 main 的 181077d。
- 否掉的方案，别再回头：头像上方悬着的白色大晶体；半透明水晶六棱台；薄台座加发光水晶环；扁平菱形镶嵌，评价是太糙。

卡面：

- 自己设计。海克斯科技风格的棱角边框，费用放在左上角的六边形里，名字横幅，原画窗口，文本框，随从底部左右是攻击和生命。法术牌没有攻击生命。卡牌是有厚度的薄板，边缘有倒角，边框带金属质感，高光随角度变化；卡面底图是贴图；文字不烧进贴图，用 SDF 文本（troika-three-text）渲染，透视缩小也清晰。随从卡的攻击徽章在左下、生命徽章在右下，和场上随从底座的徽章位置一致。
- 边框按地区配色：德玛西亚金白，诺克萨斯红黑，艾欧尼亚粉紫，弗雷尔卓德冰蓝，中立石灰。英雄卡用带纹饰的边框，小兵野怪亚龙用素边框，一眼分得出。
- 原画用 Data Dragon 的竖版加载图裁切。手牌缩略图和场上随从用头像图。
- 中文字体用霞鹜文楷或思源宋体的粗体，数字用带描边的西文字体。字体按卡池用到的字做子集。验收：1080p 下手牌上的文字不悬停就能读。
- 分辨率基准 1920×1080，等比缩放适配窗口，最窄支持 1280 宽。

### 5.5 动画总则

- 每个引擎事件对应一段动画。没有"直接变数字"的事件。
- 动画串行播放，一个事件播完再播下一个。同一批发生的事件（群体伤害、同时死亡）并行播放。
- 时长以炉石为基准，单个事件 0.3 到 0.8 秒，一回合内连续事件总时长控制在合理范围，玩家不觉得拖。
- 缓动用自然曲线：出牌落地是先快后慢带一点回弹，攻击是蓄力慢、冲出快、回位慢。
- 重要事件带屏幕反馈：英雄受重伤时屏幕轻微震动，大招级法术时棋盘闪一下。幅度要小，频繁出现的事件不震屏。
- 随机和节奏：同一种动画允许小幅随机（粒子数量、音效音高），避免机械重复感。

### 5.7 音效与音乐

四条音量通道，设置页各自可调：主音量、音乐、音效、语音。

音乐和环境音：

- 主菜单一首循环，对局一首循环，胜利和失败各一段短的收尾，都已由用户试听选定，记在 `scripts/data/audio-sources.json`。对局音乐音量偏低，不盖过音效。
- 棋盘有环境音循环：峡谷的风、水声、鸟叫，很轻，同样已选定。
- 语音播放时音乐和环境音自动压低，播完恢复。

音效分 47 类，每类一个音效，由用户在试听页（`pnpm audition:audio` 生成）听完选定，候选和选定都记在 `scripts/data/audio-sources.json` 的 selected 字段。重复感靠下面的音高随机浮动解决；以后某类听腻了，再从候选里加第二个变体。分类：

- 界面：悬停、点击、按钮按下、拖起、放下、取消。
- 卡牌：抽牌、出牌落地、法术施放按 fx 分五种（火、冰、光、影、物理）、增益、减益、回手、变形、爆牌。
- 战斗：挥击、命中轻、命中重、英雄受伤、死亡碎裂、破盾、结冰、碎冰。
- 职业：四个英雄技能各一个专属音效。
- 流程：回合开始、回合结束、疲劳、胜利、失败。

语音：

- 每个英雄随从入场时说一句登场台词，死亡时说一句。
- 第一版用英雄的选用语音做登场、禁用语音做死亡。来源见 5.9。攻击语音第一版没有：完整语音库在游戏的 wwise 音频包里，要另外解包，以后评估。
- 同一时刻只播一条语音，新的来了打断旧的。连续入场多个随从时，只有最后一个说话。

一致性和分层：

- 所有音频过同一条归一管线（scripts/normalize-audio.ts），不同来源的素材听起来是一套。响度目标以实现为准，细节在 NOTES.md 的"音效和音乐素材（M4 准备）"一节：

| 类别 | 目标 | 说明 |
| --- | --- | --- |
| 音效 | 最大瞬时响度 -18 LUFS | 起音很尖、很短的音效会被真峰值上限卡住而比目标轻，这是有意的，不硬压 |
| 语音 | 积分响度 -18 LUFS | |
| 胜负收尾 | -18 LUFS | |
| 音乐 | -20 LUFS | |
| 环境音 | -30 LUFS | |

  真峰值上限 -1 dBTP，统一采样率，输出 ogg，带 mp3 兜底。分镜里不写音量，靠这张表。
- 战斗事件的声音固定分三层：动作层（挥击、冲刺）、材质层（命中轻重、碎裂、结冰）、语音层。每层用各自选定的那一个音效，靠音高浮动避免重复感。
- 按棋盘位置做左右声像：左边的随从攻击，声音偏左。

技术：

- 用 Howler.js 走 Web Audio。小音效合成一张音效表减少请求。
- 同一音效同时最多 4 个实例，超出的不播。
- 音高随机浮动正负 5%，避免重复感。
- 浏览器要求用户手势之后才能出声，所以主菜单第一次点击时初始化音频。

### 5.8 表现层架构

引擎瞬间算完一个动作，吐出一串事件；表现层负责把这串事件演出来。两者之间隔一层"显示局面"：

```
引擎局面 ──applyAction──▶ 新局面 + 事件[]
                                │
                        事件队列（串行，同组并行）
                                │
                           导演 Director
                 每个事件 → 一条 GSAP 时间线 + 音效 + 显示局面更新
                                │
                      Three.js 场景按显示局面渲染
```

- 显示局面落后于真实局面，动画播完才追上。玩家看到的永远是显示局面。
- 事件里带表现需要的全部信息：来源、目标、数值、变化前后的值、同组 id、fx 类型。导演不反查引擎。
- 每类事件一个动画模块，输入是事件和场景对象，输出是 GSAP 时间线。模块之间不耦合，方便逐个打磨。
- 布局函数给出每个槽位（手牌第 n 张、场上第 n 个随从、英雄、牌库）的坐标，所有动画以槽位坐标为起止点。场上随从数变化时，先算新布局，再让随从滑过去。
- 输入什么时候锁定、操作依据哪个局面，以 6.6 为准：显示局面追上真实局面之前锁定输入，合法操作永远来自真实局面。
- AI 的每个动作之间插一个"思考"间隔事件，导演把它当成等待。

### 5.9 素材来源与管线

英雄美术，Data Dragon，不用鉴权：

- 版本列表：`https://ddragon.leagueoflegends.com/api/versions.json`
- 英雄中文名和数字 id：`https://ddragon.leagueoflegends.com/cdn/<版本>/data/zh_CN/champion.json`
- 头像（120×120）：`https://ddragon.leagueoflegends.com/cdn/<版本>/img/champion/<Key>.png`
- 竖版原画（308×560）：`https://ddragon.leagueoflegends.com/cdn/img/champion/loading/<Key>_0.jpg`。这个地址不带版本号，带了会返回 403；头像地址带版本号正常。

中文 `champion.json` 里 `name` 是称号（如"迅捷斥候"），`title` 才是英雄名（如"提莫"），和英文数据正好相反；`key` 是数字 id，语音地址用它。卡池里的中文名以 `title` 为准。

英雄语音，CommunityDragon 的游戏数据镜像：

- 选用语音：`https://raw.communitydragon.org/latest/plugins/rcp-be-lol-game-data/global/zh_cn/v1/champion-choose-vo/<数字 id>.ogg`
- 禁用语音：同路径下的 `champion-ban-vo/<数字 id>.ogg`
- 这两个路径是按现有镜像结构写的，做抓取脚本时以实际能下到的为准。中文语音不全时退到 `default` 目录的英文语音。

图标和野怪图，都验证过能下到：

- 技能图标：`https://ddragon.leagueoflegends.com/cdn/<版本>/img/spell/<技能 key>.png`，英雄技能用对应英雄的技能图标（盖伦 `GarenE`、德莱厄斯 `DariusExecute`、阿狸 `AhriQ`、艾希 `Volley`）。
- 关键词 buff 图标：同目录的技能图标、`img/spell/Summoner*.png` 召唤师技能、`img/item/<id>.png` 物品、`img/passive/<文件>.png` 被动里挑，每个关键词固定一张。
- 小兵、野怪、亚龙：CommunityDragon 的 `game/assets/characters/<单位>/hud/<名>_square.png`，例如 `sru_baron/hud/baron_square.png`，峡谷单位目录有 70 个，纳什男爵、各色亚龙、远古巨龙、石甲虫、魔沼蛙、迅捷蟹、峡谷先锋、小兵都有；文件名不带 `sru_` 前缀，抓取脚本按目录列表取。
- 客户端 UI 件（按钮、进度条、下拉框）：CommunityDragon 的 `plugins/rcp-fe-lol-uikit/global/default/images/`，给 React 菜单用。

法术和非英雄卡的配图：

- 符文之地传说（LoR）的官方卡牌原画：dd.b.pvp.net 上的单张卡牌图，2048×1024。整包 zip 已经关闭（403），单张图能下到。法术牌大多用它，按卡名对应，用户已确认接受。
- 配图规则：有大图的用大图，LoR 原画或 LoL 皮肤原画裁切；小兵、野怪、亚龙这些只有 128 像素峡谷头像的先用头像，标"以后生成大图"，纳什男爵优先补。
- 英雄技能的配图不和同名或同效果的法术共用一张图，免得玩家混淆。
- 每张卡用哪张图记在 `scripts/data/card-art.json`，抓取脚本按它取图，加卡先加映射。

音效和音乐：不自己录。音效只收 CC0 授权的素材，来源和授权逐条记在 `scripts/data/audio-sources.json`（第一轮 50 个来源全部 CC0-1.0；没用 freesound，它要登录才能下原始文件），按 5.7 的分类整理。音乐由你自己放几首进 `public/audio/music/`，占位先用 CC0 曲子。

管线：

- `scripts/fetch-art.ts`：按卡池里的 champion 字段拉头像和竖版原画到 `public/art/`。
- `scripts/fetch-voice.ts`：拉语音到 `public/audio/voice/`。
- `scripts/fetch-icons.ts`：按关键词和英雄技能的映射表拉技能、物品、被动图标，按单位列表拉野怪图，到 `public/art/icons/`。
- `scripts/fetch-sfx.ts`：按 `scripts/data/audio-sources.json` 下载原始音效到 `assets-src/`，不进构建。
- `scripts/normalize-audio.ts`：按 5.7 的响度目标归一音效、语音、音乐，统一格式，输出到 `public/audio/` 并生成清单。
- `scripts/pack-atlas.ts`：把卡框、徽章、图标、粒子贴图打成图集。
- `src/assets/manifest.ts`：所有资源的清单，加载页按它预载。
- 卡框和棋盘贴图没有现成的：用 AI 生图出底图，再切图、做高度图，走图集；徽章、法力条这类简单件用矢量画。不需要建模素材：卡牌、随从底座、水晶枢纽都是几何体加贴图。

### 5.10 性能预算

- 1080p 下稳定 60fps，M1 芯片的 MacBook 为基准机。
- 场上最多 14 个随从加 20 张手牌同时在屏，加一个群体法术的粒子，不掉帧。
- 粒子总数上限 2000，超出时新粒子不生成。
- 对局开始前预载本局两套卡组的美术和语音，其余不载。加载页出现时间不超过 3 秒（本地资源）。
- 字体做子集，只带卡池用到的字。
- 阴影贴图尺寸要克制：一盏方向光一张 2048 的阴影贴图，不够再考虑级联。
- 设备像素比上限 2，更高的屏幕按 2 渲染。
- 后处理第一版只开 bloom，别的效果要先证明帧预算够。

## 6. 技术架构

### 6.1 技术栈

- TypeScript，pnpm，Vite。
- 引擎：纯 TypeScript，不依赖 DOM，能在 Node 里跑测试和命令行对局。
- 对局场景：Three.js，做真 3D。固定透视镜头斜俯视棋盘，方向光加环境光，实时阴影，ACES 色调映射，泛光后处理。选它而不是 2D 引擎的原因：真实的纵深、光照、投影和卡牌倾斜靠 3D 引擎直接得到，不用逐个模拟；2D 引擎只能手工模拟透视和投影，上限低、打磨成本高。不需要建模素材，卡牌、随从底座、水晶枢纽都用几何体加贴图，卡面文字用 canvas 合成贴图。渲染器先用 WebGL2，Three.js 的 WebGPU 渲染器以后再评估，第一版不依赖它。
- React 不参与对局画面的渲染。它只画文字为主的界面，叠在画布上面一层。两层的边界是：会动、要发光、有粒子、有纵深的东西在 Three.js 场景里；要滚动、要筛选、要输入文字的东西在 React 里。
- 动画编排：GSAP，驱动 Object3D 的位置、旋转、缩放和材质参数。每个事件一条时间线，串并行组合方便，缓动曲线齐全。
- 后处理：bloom 只对自发光材质生效，用图层做选择性泛光，或者直接用 pmndrs 的 postprocessing 库，别让徽章上的数字也晕开。粒子发射器自己写，几百行，不受库版本牵制。
- 场景内文字：troika-three-text，SDF 渲染，字体子集化后加载。
- 调试工具：GSAP 的 GSDevTools 拖时间轴，lil-gui 实时调光照、材质、时长，都只进开发构建。
- 菜单、卡组编辑、设置、悬停卡面、日志这些以文字为主的界面：React，叠在画布上层。
- 音频：Howler.js。
- 测试：Vitest。
- 存档：localStorage，存设置、自组卡组、战绩。

### 6.3 引擎约束

- 纯函数。`applyAction(state, action)` 返回新局面和事件，不改入参。局面用不可变更新。
- 确定性。所有随机数来自局面里的种子，同一局面加同一动作结果一定相同。
- 合法性和执行分开。`listLegalActions` 列出来的动作，`applyAction` 一定能执行。非法动作返回错误，不抛异常。
- 隐藏信息只在视图层过滤。引擎内部局面是完整的，`maskHidden` 和 `visibleState` 负责遮。
- 引擎不知道 AI 和表现层的存在。事件是引擎和表现层之间唯一的接口。

### 6.4 事件

引擎每执行一个动作返回一个事件数组，表现层只靠它演出。每个事件带：

- `kind`：事件类型。
- `group`：同组 id。群体伤害打到五个随从是五个 damage 事件共一个 group，表现层并行播放。
- 来源和目标的引用，数值，变化前后的值。例如 damage 带 `source`、`target`、`amount`、`healthBefore`、`healthAfter`、`shieldAbsorbed`。
- `fx`：从卡牌数据原样带过来的表现类型。
- 位置信息：召唤带入场位置，死亡带离场前的位置，回手带回到手牌第几张。

引擎事件类型：

| 事件 | 说明 |
| --- | --- |
| mulligan_start | 起手牌发好，进入换牌阶段 |
| mulligan_done | 一方换牌完成，带换掉的牌和新抽的牌 |
| game_start | 双方都换完，进入对局 |
| turn_start / turn_end | 带是哪一方 |
| draw / burn / fatigue | 抽牌、爆牌、疲劳 |
| card_played | 从手牌打出一张牌，随从和法术都发 |
| minion_summoned | 随从入场，`via` 为 play、effect、hero_power 之一。"出随从"和"召唤衍生物"两种动画靠它区分 |
| spell_cast / hero_power_used | 法术生效、英雄技能生效，带 chosen 目标 |
| trigger | 某个效果触发，带 source、时机（battlecry、deathrattle、combo、turn_start、turn_end、on_kill、script）和 chosen 目标。script 是菲奥娜、泰达米尔这类脚本卡的脚本生效时发，带脚本名。在该效果的动作事件之前发出，"战吼选目标"的动画对应它 |
| attack | 带攻击方和目标 |
| damage / heal | 带前后值 |
| death | 带离场前位置 |
| buff | 增益和减益都是它，数值可以为负，带前后值 |
| silence | |
| freeze / unfreeze | |
| shield_broken / stealth_lost | |
| bounce / transform | 变形带变成了哪张卡 |
| mana_changed | 带前后值和原因 |
| game_over | 带胜者或平局 |

`ai_thinking` 不是引擎事件。引擎不知道 AI 的存在，驱动 AI 的对局层在 AI 的两个动作之间往同一条事件队列里插一个自己的等待事件，导演当成普通事件播。表现层接收的事件类型是引擎事件加对局层事件，放在一个联合类型里。

### 6.5 局面模型

局面是纯数据，没有 Set、Map、类实例，能直接 JSON 序列化。回放夹具和存档都靠这一点。

```ts
type GameState = {
  phase: 'mulligan' | 'playing' | 'over';
  turn: number;               // 从 1 开始，每次换人 +1
  current: 0 | 1;             // 当前行动的玩家
  players: [PlayerState, PlayerState];
  rng: RngState;
  winner?: 0 | 1 | 'draw';
};

type PlayerState = {
  heroClass: HeroClass;
  hero: { health: number; maxHealth: number };
  mana: { max: number; current: number; temp: number };
  deck: CardInstance[];
  hand: CardInstance[];
  board: MinionState[];       // 从左到右
  fatigue: number;
  heroPowerUsed: boolean;
  cardsPlayedThisTurn: number;
  mulliganDone: boolean;
};

type MinionState = {
  instanceId: number;
  cardId: string;
  attack: number; health: number; maxHealth: number;   // 含增益后的当前值
  buffs: Buff[];              // 每条记来源和持续时间，沉默时清空
  keywords: Keyword[];        // 当前拥有的关键词，圣盾也在这里，失去圣盾就是移除它
  attacksThisTurn: number;
  enteredTurn: number;        // 召唤失调判定，变形出来的随从重置为当前回合
  frozenAt?: number;          // 冻结发生在第几回合
  silenced: boolean;
  summonOrder: number;        // 亡语和回合触发的顺序
  usedOnce?: string[];        // 每局只触发一次的效果里已经用掉的，泰达米尔用
};
```

动作：

```ts
type Action =
  | { kind: 'mulligan'; player: 0 | 1; replace: number[] }   // 换牌阶段，哪一方、要换掉的手牌下标，可以为空
  | { kind: 'play_card'; handIndex: number; position?: number; target?: TargetRef }
  | { kind: 'attack'; attacker: TargetRef; target: TargetRef }
  | { kind: 'hero_power'; target?: TargetRef }
  | { kind: 'end_turn' };

type TargetRef = { side: 0 | 1; kind: 'hero' } | { side: 0 | 1; kind: 'minion'; instanceId: number };
```

换牌阶段只有 mulligan 合法，每方提交一次，顺序不限。两边都提交后，引擎对每一方先从牌库顶补抽同样张数（新牌放回被换掉的位置），再把换掉的牌洗回牌库，然后进入 playing 并开始先手的第一回合。`createGame` 有 `skipMulligan` 选项，测试和命令行对局用。

### 6.6 输入时序

- 合法操作永远来自真实局面。界面调 `listLegalActions` 拿到能做的事，表现层不自己判断。
- 玩家输入在显示局面追上真实局面之前锁定。锁定期间不能拖手牌、不能选随从，可以悬停看牌和快进动画。
- 这样玩家看到的和能操作的始终是同一个局面，不会拖一个实际已经死了、画面上还在的随从。代价是连续操作之间要等动画，用短时长（玩家自己动作的动画大多在 0.6 秒内）和快进把等待压到感觉不到。
- 对方回合全程锁定。

### 6.7 测试

- 每个关键词一组单元测试，覆盖定义里的每一句话。例如潜行：不能被攻击、不能被指向、攻击后失去、群体伤害打得到、潜行的嘲讽不挡人。
- 每张卡一个测试，用场景 DSL 搭局面：`scenario().board(0, ['卡特琳娜']).board(1, ['近战小兵', '石甲虫']).play(...)`，断言结果和事件序列。
- 换牌阶段的测试：换 0 张、换全部、法力药水不能换、双方提交顺序不影响结果。
- 不变量检查：每次 `applyAction` 之后，生命不超上限、随从不超 7、手牌不超 10、法力在 0 到 10 之间。测试模式下打开。
- 事件完整性：每种事件类型至少有一个测试断言它被发出，并且字段齐全。表现层靠事件演出，漏发事件玩家就看不到发生了什么。
- AI 互打冒烟：L1 对 L1，随机种子跑 1000 局，不报错、不卡死、每方不超过 60 个回合（turn 不超过 120）。两套控制卡组靠疲劳分胜负正常也要打到 turn 70 左右，这个上限留了余量。四套预组互相打的胜率都落在 30% 到 70% 之间，不然调卡。
- 表现层：录一局固定种子的事件流做成夹具，导演回放它，人工过一遍每种动画。没有自动化的视觉断言，靠 5.6 清单逐条验收。

## 8. 已经替你定下的选择

这些都可以改，改了告诉我哪条。

1. 规则照搬炉石经典模式，不自创基础规则。原因：规则成熟、你熟、省设计时间，精力放在卡和表现上。
2. 职业按地区分，先做德玛西亚、诺克萨斯、艾欧尼亚、弗雷尔卓德四个，风格分别是铺场增益、快攻、法术节奏、冻结控制，四种打法差别够大。
3. 随从全部是英雄，每个英雄只属于一个地区。中立卡用小兵、野怪、亚龙、虚空生物、约德尔人。
4. 英雄技能统一 2 费。
5. 第一版不做武器和英雄牌，所以英雄不能攻击，冻结只针对随从。
6. 英雄美术用 Data Dragon 原图，语音用 CommunityDragon 的选用和禁用语音。
7. 对局场景用 Three.js 做真 3D：固定透视镜头斜俯视、方向光加环境光、实时阴影、ACES 色调映射、泛光后处理，渲染器先用 WebGL2。动画用 GSAP，文字类界面用 React 叠在上面，React 不画棋盘。不用 2D 引擎，理由见 6.1：M3 骨架用 2D 做出来是平的，真实的透视、光照和投影在 2D 里只能手工模拟，上限低、打磨成本高。
8. 引擎和表现层之间只靠事件通信，表现层维护自己的显示局面。
9. 初始卡池约 86 张：四个职业各 14 到 16 张，中立 24 张。没有稀有度，所有卡最多带 2 张。
10. AI 先做逐动作贪心，再做回合内搜索。贪心对任何新卡都自动适用，不用为每张卡写策略。
11. 先把表现骨架搭完（M3）再逐条打磨（M4），不在搭骨架时就追求精细。
12. 视觉语言取自 LoL 对局（峡谷战局），关键词和状态用峡谷里的护盾、buff 图标、水晶枢纽表示，不复刻别的卡牌游戏的外观。攻击和生命用随从底座内左下、右下两个对称徽章，和卡面位置一致，这是卡牌游戏的通用做法，不算照搬。
13. 表现层的每个做法都要能对应到 5.0 对照表的一行，并且尽量站在"直接"一侧：棋盘是浮雕低模不是贴图，文字用 SDF 不烧贴图，悬停大卡在场景内不用 DOM，图标和野怪图用 LoL 自己的素材不自己画，音效过同一条归一管线。
14. 英雄随从的攻血分配按 LoL 定位（3.7），平衡只沿定位方向调。
